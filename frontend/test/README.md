# 브라우저 로그인 유지 검증

`npm run test:auth`는 Node.js의 내장 테스트 러너와 Axios 테스트 어댑터를 사용한다.
실제 계정이나 개발 DB에 접속하지 않는다.

검증 대상:

- 탭별 Access Token이 없어도 Refresh Token 쿠키로 인증 복구
- 앱 시작 시 이전 계정의 탭 토큰을 쿠키의 계정으로 갱신
- 동시에 필요한 재발급 요청 병합
- 로그인 제출 직전 기존 인증 확인
- Web Locks를 지원하는 환경에서 로그인·로그아웃·재발급 순서 보장
- 인증 거절과 네트워크·서버 오류 구분
- 로그아웃 성공 후 탭 간 변경 알림 전달
- 인증이 변경된 뒤 도착하는 오래된 응답 무시

실제 서버와 브라우저에서는 다음을 확인한다.

1. A탭에서 로그인한 뒤 B탭으로 `/login`을 열면 같은 계정의 대시보드로 이동한다.
2. 모든 탭을 닫고 다시 접속해도 유효한 Refresh Token 쿠키가 있으면 인증을 복구한다.
3. 로그인 화면 두 개를 열고 한쪽에서 로그인하면 다른 쪽도 기존 계정으로 이동한다.
4. 한 탭에서 로그아웃하면 다른 탭의 화면과 알림 연결도 정리된다.
5. 네트워크 장애 중 앱을 열면 로그인 화면 대신 재시도 안내가 보인다.
6. 로그아웃 요청이 실패하면 완료된 것처럼 화면을 전환하지 않는다.

쿠키 유효기간과 토큰 만료는 기존 서버 정책을 따른다.
Access Token은 탭별 저장소에 보관하고, 브라우저 공통 저장소에는 변경 알림만 기록한다.
변경 알림을 받은 탭은 페이지를 다시 로드하므로 작성 중인 입력은 사라질 수 있다.
Web Locks를 지원하지 않으면 인증 재확인과 탭 간 동기화는 동작하지만,
정확히 동시에 제출한 로그인 요청의 직렬화는 보장하지 않는다.
이 개선은 같은 브라우저 프로필의 화면 상태를 일치시키는 기능이다.
다른 브라우저·기기의 동시 로그인을 제한하거나 이미 발급된 토큰을 서버에서 폐기하지는 않는다.
